ABSTRACT

Efficient communication between college management, academic faculties, and students is essential for high institutional productivity. Traditional wooden bulletin boards and chaotic messaging groups often fail due to paper damage, physical location constraints, forged announcement forwards, and poor search capabilities.

Campus Notify addresses these critical problems by delivering a robust, object-oriented notification engine engineered in Core Java (JDK 17+). Built on a clean Model-View-Controller (MVC) architecture, the system provides:

  • Strict Role-Based Access Control (RBAC) separating Super Administrators, Departmental Faculty, and Student Viewers.
  • Persistent Flat-File I/O Storage (via BufferedReader and PrintWriter), ensuring announcements persist across sessions.
  • O(N) Keyword Search & Multi-Criteria Filtering based on Announcement Category (Academic, Exam, Events, Placement) and Priority Level (Urgent, High, Normal).
  • Departmental Analytics & Statistics calculating distribution ratios and priority breakdowns.
  • Dual-Interface Support: An interactive Command-Line Interface (CLI) and an accompanying modern Web Dashboard integrated with Google Firebase and local resilient caching.

The system's reliability and security are validated through a 9-pillar automated verification suite with 36 automated test cases achieving a 100% pass rate.

Keywords: Core Java, Object-Oriented Programming (OOP), Model-View-Controller (MVC), Role-Based Access Control (RBAC), File I/O Persistence, Collections Framework, Google Firebase.

CHAPTER 1: INTRODUCTION

1.1 Background & Motivation

In engineering colleges and university campuses, dozens of circulars are published weekly: examination timetables, submission deadlines, cultural festival schedules, training and placement drives, fee notifications, and laboratory schedules. Relying on physical bulletin boards results in missed deadlines and unread notices, while group messaging platforms (such as WhatsApp) suffer from chat spam and lack of authorization.

1.2 Problem Statement

Existing academic notification practices suffer from three main drawbacks:

  1. Absence of Authorization & Forgery Vulnerability: Anyone can forward misleading exam notices without cryptographic or administrative authority verification.
  2. Information Overload & Zero Searchability: Students waste excessive time scrolling through hundreds of messages to find notices issued weeks prior.
  3. Lack of Categorization & Priority Signals: Urgent notices (e.g., examination postponement or sudden emergency closures) get lost among club activity promotions.

1.3 Objectives of the Project

  • Implement a pure Core Java domain model demonstrating Encapsulation, Inheritance, Abstraction, and Polymorphism.
  • Provide robust File I/O persistence for offline durability without requiring external database dependencies.
  • Deliver an interactive Command-Line Interface (CLI) menu with input sanitization and exception handling.
  • Implement a Web Dashboard with real-time cloud data synchronization (Google Firebase) and responsive UX.
  • Enforce strict Role-Based Access Control to prevent unauthorized circular posting or deletion.

3.2 Architectural Model

The architecture adheres to the Model-View-Controller (MVC) software design pattern:

  • Model (User.java, Notification.java): Encapsulates academic entities, data validation, and serializable attributes.
  • Controller (NotificationManager.java): Executes business logic, CRUD operations, keyword searching, category filters, analytics, and file persistence.
  • View (Main.java & Web Dashboard): Presents formatted output tables to the user and captures validated inputs.

CHAPTER 4: OBJECT-ORIENTED METHODOLOGY & JAVA CONCEPTS

4.1 Encapsulation & Data Hiding

All data members in User and Notification are marked with the private access modifier. State inspection and mutation occur through getter and setter methods that enforce validation (e.g., rejecting empty titles, formatting dates).

4.2 Constructor Overloading

Constructors are overloaded to accommodate both runtime generation (with current timestamps) and deserialization from persistent disk storage (parsing historic timestamps).

4.3 Collections Framework & Iterators

The application utilizes java.util.ArrayList for dynamic in-memory notice buffering and java.util.Iterator for deletion operations to prevent ConcurrentModificationException during traversals.

4.4 File I/O Streams

Data persistence is implemented using BufferedReader and PrintWriter with custom delimiter-separated serialization (|||), preventing field corruption when descriptions contain standard punctuation.

public String toFileString() {
    return id + "|||" + title + "|||" + description + "|||" + 
           category + "|||" + priority + "|||" + author + "|||" + 
           DATE_FORMAT.format(datePosted);
}

5.3 Safe Deletion & Search in NotificationManager.java

public boolean deleteNotification(int id) {
    Iterator<Notification> it = notifications.iterator();
    while (it.hasNext()) {
        if (it.next().getId() == id) {
            it.remove();
            saveToFile();
            return true;
        }
    }
    return false;
}
