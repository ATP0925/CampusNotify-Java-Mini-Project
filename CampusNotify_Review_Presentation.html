Introduction & Academic Background:

  • Institutional Communication Imperative: Higher educational institutions generate dozens of time-critical circulars every week—exam timetables, hall-ticket releases, scholarship deadlines, revaluation alerts, and placement recruitment drives.
  • Multi-Tier Stakeholder Ecosystem: The communication flow bridges three core groups: Institutional Administration (Principal/Deans), Department Faculty Heads & Mentors, and Students across multiple engineering divisions.
  • The Operational Challenge: Reliance on physical wooden notice boards and unorganized messaging groups leads to missed deadlines, lack of audit trails, and student distress.
  • Academic Mini-Project Foundation: Designed as a Second Year Information Technology Mini-Project demonstrating the real-world application of Core Java Object-Oriented Programming (OOP), File I/O Streams, and Collections Framework.
Campus Notify | VPPCOE&VA Slide 3

Problem Statement & Motivation:

  • Information Clutter & Missed Deadlines: In informal WhatsApp/Telegram groups, vital circulars get buried beneath hundreds of casual chat messages, leading to students missing scholarship and exam submission deadlines.
  • Zero Authenticity & Falsification Risk: Informal messaging lacks role verification. Falsified or edited circular screenshots circulate freely with zero administrative audit trails.
  • Lack of Search & Category Indexing: Corridor bulletin boards and chat groups offer no search mechanisms. Locating an older circular requires tedious manual physical searches or endless chat scrolling.
  • Physical Proximity Barriers: Commuting, absent, or ill students cannot view physical campus bulletin boards in real time.
  • UN Sustainable Development Goals (SDG) Alignment: Directly aligns with SDG 4 (Quality Education) by ensuring equitable information access and SDG 9 (Industry, Innovation & Infrastructure) through digital modernization.

Objectives of the Project:

  • Centralized & Authoritative Repository: To develop a single authentic digital platform eliminating fragmented physical boards and chat noise.
  • Role-Based Access Control (RBAC): To implement strict privilege boundaries separating authorized notice publishers (Admin/Faculty) from student viewers.
  • Core Java Object-Oriented Principles: To apply Encapsulation, Constructor Overloading, and Data Abstraction in engineering domain models (Notice, User, Role).
  • Restart-Safe Local File I/O Persistence: To ensure 100% circular retention across system restarts using Java BufferedReader and PrintWriter streams.
  • Multi-Platform Accessibility: To deliver both an interactive terminal CLI scanner and a responsive web dashboard synchronized with Google Firebase.

Proposed Solution & System Architecture (MVC):

Model Layer (Domain Entities)

• Notice.java: Encapsulates title, category, priority, date, author, and status.
• User.java & Role.java: Enforces RBAC identity boundaries.
• Enums: Category (Academic, Exam, Placement, Events) and Priority (Urgent, High, Normal).

View Layer (Dual Presentation)

• Terminal CLI Driver: Interactive Scanner menu with ANSI color formatting for terminal execution.
• Modern Web Dashboard: Responsive semantic HTML5, CSS3 Grid, sticky modal dialogs, and instant search bars.

Controller & Storage Layer

• NoticeService.java: Executes CRUD, search, priority sorting, and validation rules.
• FileStorageEngine.java: Java stream persistence reading and writing delimited records.

Cloud Sync & Offline Layer

• Google Firebase Cloud Firestore snapshot listeners for multi-device live sync.
• Browser LocalStorage fallback ensuring full offline viewing when disconnected.

Core Java OOP Design Highlights:

  • Encapsulation & Data Hiding: All entity attributes in Notice.java are declared private. Data mutation is strictly governed by public getters and setters with internal string sanitization.
  • Constructor Overloading: Implemented dual constructors: one for interactive creation (auto-generating UUID and timestamps) and an overloaded constructor for disk file deserialization.
  • Collections Framework (ArrayList & Iterator): Notices are managed dynamically in ArrayList<Notice>. Safe traversal and removal use Java Iterator to avoid ConcurrentModificationException.
  • Java File I/O Stream Persistence: Uses BufferedReader and PrintWriter to serialize notices to notifications_data.txt using delimited tokens (#DATA#), ensuring zero data loss on restart.
  • Lambda Expressions & Comparators: Utilizes Java 8+ Comparator lambdas to sort notices automatically by priority urgency and publication timestamp.

Web Dashboard, Security & Governance:

  • Super Admin Restricted Theme Studio: To preserve institutional visual integrity, color customization is strictly restricted to Super Admin (role === 'ADMIN'); regular students view a clean Academic Royal Blue theme.
  • Student Privacy Shield & Telemetry Isolation: Server telemetry metrics and traffic counters are separated from student feeds and relocated to the Super Admin Governance Desk.
  • End-to-End Encryption (E2EE): Notice board payloads and student inquiries are protected via cryptographic hashing, securing data in transit across public campus Wi-Fi networks.
  • Universal Cross-Device Responsiveness: 100% responsive across mobile phones, tablets, and desktops. Features sticky header/footer modals, compact mobile avatars, and 2-column touch buttons.
  • Production Cloud Deployment: Live on Google Firebase Hosting: https://campnotify-eef91.web.app with continuous cloud Firestore sync.
